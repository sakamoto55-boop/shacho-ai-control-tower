# AI参謀（solo-ai-sanbo）

一人で事業をやる人のための、記録と材料出しの道具です。

**決めるのはあなた。参謀は「数える」と「書く」をやります。**

会社の管制塔（このリポジトリのルートにある `src/`）とは別物で、依存もありません。
一人運用に要らない概念（部署、担当者への振り分け、承認フロー）を持ち込まないために分けています。

## 何のために作ったか

一人で複数の稼ぎ方を試している段階だと、次の2つで詰みます。

1. **どれが儲かっているのか分からない。** 売上だけ見ていると、時間を食っているだけの柱に気づけない。
2. **放置した案件がそのまま消える。** 一人だと、他の誰も気づかない。

だからこの道具は、**柱ごとの「1時間あたりいくら生んだか」**と、**放置されている案件**の2つだけを、確実に見えるようにします。

## 参謀の原則

- AIは方針を決めません。事実と選択肢を出し、選ぶのはあなたです。
- AIは**金額・納期・保証・契約条件**を決めません。文中は`【金額】`のまま残します。
- AIは何も送りません。返信も投稿も見積も、**下書きまで**です。
- 数字の解釈も押し付けません。「Aが高い、Bが低い」までを出します。

## はじめかた

```bash
cd solo-ai-sanbo
npm install
cp .env.example .env      # APIキーなしで動きます（AI_PROVIDER=mock）
npm run sanbo             # ヘルプが出ます
```

以後 `npm run sanbo -- <コマンド>` で使います。毎日打つので、シェルに登録しておくと楽です。

```bash
alias sanbo='npm --prefix ~/path/to/solo-ai-sanbo run --silent sanbo --'
```

## 初日にやること（3分）

試している柱を全部登録します。**見直し日（--review）と撤退基準（--target）を最初に入れる**のが肝心です。
決めないまま始めた柱は、やめどきが分からなくなって何ヶ月も残ります。

```bash
sanbo pillar add 解体の個人受注 --kind service  --review 30日後 --target 30万
sanbo pillar add 発信           --kind content  --review 60日後 --target 5万
sanbo pillar add AI活用の受託    --kind contract --review 30日後 --target 20万
```

進行中の案件も入れておきます。

```bash
sanbo deal add 空き家解体 --pillar 解体 --client 田中様 --amount 150万 --cost 60万 --next "現地見積" --due 明日
```

## 毎日やること（1分）

1日の終わりに、使った時間を1行だけ。これがないと時給が出ず、柱を比べられません。

```bash
sanbo time 240 --deal 空き家解体 --cat delivery --note "現地調査と積算"
sanbo time 90  --pillar 発信 --cat content
```

お金が動いたら記録します。

```bash
sanbo money in  150万 --deal 空き家解体 --label 解体一式
sanbo money out  60万 --deal 空き家解体 --label 処分費と回送
```

朝はこれだけ読みます。

```bash
sanbo brief
```

```
【AI参謀｜朝の材料】2026-08-19
決めるのはあなたです。ここには事実と選べる手だけ置きます。

■ 期限を過ぎた次アクション 1件
・事務所の内装相談（佐藤様／解体の個人受注／引き合い／金額未定）
  期限2026-08-18／図面をもらう
  - 今日やる（`sanbo deal touch <id>` で期限を引き直す）
  - 期限を先に延ばす（`sanbo deal set <id> --due 3日後`）
  - 落とす（`sanbo deal move <id> lost`）
```

## 週に一度やること（5分）

```bash
sanbo review
```

```
--- 柱ごとの成績（時給の高い順） ---
・解体の個人受注（受注仕事／testing）
    時間 5.5時間／粗利 90万円／163,636円/時
・発信（発信／testing）
    時間 7時間／粗利 8万円／11,429円/時
・AI活用の受託（受託・代行／testing）
    時間 3時間／粗利 0円／0円/時

■ 時間あたりで見ると差が出ています
一番高い: 解体の個人受注 163,636円/時
一番低い: AI活用の受託 0円/時
  - 解体の個人受注に来週の時間を寄せる
  - AI活用の受託の単価か進め方を変える
  - AI活用の受託を止めて時間を空ける
  - 判断材料が足りないので、もう1週分ためる
```

**「何で稼ぐか」を決めるのは、この画面です。** 気分ではなく、時間あたりの粗利で比べます。

## 下書きを頼む

```bash
sanbo draft reply "空き家の解体をお願いしたいのですが、だいたいいくらでしょうか"
sanbo draft estimate "木造2階建て 約40坪の空き家解体" --context "前面道路4m 残置物あり"
sanbo draft content "解体の見積で見るべき3つの項目" --pillar 発信
```

見積の下書きは**金額を入れません**。項目と、漏れやすいもの（廃材処分費、重機回送、アスベスト事前調査など）を並べるところまでです。金額は現地と原価を見て自分で入れます。

## コマンド一覧

`sanbo` だけ打つと全部出ます。

- `pillar add / list / set` — 柱（何で稼ぐか）
- `deal add / list / move / touch / set` — 案件
- `time <分> / time list` — 時間
- `money in / money out` — お金
- `brief` — 朝の材料
- `review [--days 7]` — 週の数字
- `draft reply|estimate|content` — 下書き

指定は**IDの先頭数文字でも、名前の一部でも**通ります（`--pillar 解体`）。
日付は `今日 / 明日 / 3日後 / 8-25 / 9月3日 / 2026-08-25`、金額は `30万 / 300000` が使えます。

## 案件の段階

`inquiry`（引き合い）→ `talking` → `quoted`（見積提出）→ `won`（受注）→ `delivering`（作業中）→ `invoiced`（請求済）→ `paid`（入金済）。行き止まりは `lost`（失注）。

請求と入金を分けているのは、一人だと入金漏れが直接生活に響くからです。
`invoiced` のまま残っている案件は、入金を記録するまで毎朝出ます。逆に入金だけ記録して段階を進め忘れた場合も、それを知らせます。

## 保存先

`./data/sanbo.json` の1ファイルだけです（`LOCAL_DB_PATH` で変更可）。
一人分の記録にデータベースは要りません。中身をエディタで開いて直せることのほうが価値があります。バックアップはこのファイルをコピーするだけです。

## AIを実物に切り替える

既定は `mock`（ルールベース、APIキー不要）です。文章の質を上げたいときだけ切り替えます。

```env
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
```

切り替えても原則は同じです。金額・納期・保証・契約条件は空欄のまま返り、送信はしません。
プロンプトは `src/ai/prompts.ts` にまとめてあるので、言い回しは自分で直せます。

## 設定

```env
AI_PROVIDER=mock            # mock | anthropic
ANTHROPIC_API_KEY=
LOCAL_DB_PATH=./data/sanbo.json
MIN_HOURLY_YEN=3000         # これを下回る柱は週次で指摘される
```

`MIN_HOURLY_YEN` は「自分の時間の値段」です。決めておかないと、安い仕事で埋まります。
