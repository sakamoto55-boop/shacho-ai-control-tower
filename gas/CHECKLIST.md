### ☐ 4-3. 1週間の試験運用

`CONFIG` の `ENABLE_NOTIFY` を `FALSE` にしておくと、
生成のみ行って `REPORT_LOG` に貯まり、経営者には届きません。
内容が安定してから `TRUE` に戻す運用をおすすめします。

- [ ] 3日連続でエラーなく動いた
- [ ] 要約の粒度について経営者から合格をもらえた
- [ ] `SUMMARY_KEYWORDS` を業務実態に合わせて調整した
- [ ] `CONFIG_MASK` に伏せ字にすべき語を追加しきった

## 異常時の復旧手順

| 状況 | 対処 |
|---|---|
| 収集が途中で止まって進まない | `resetCollectionState` を実行 → `startDailyCollection` を再実行 |
| トリガーが増殖している | `deleteAllTriggers` を実行 → `setupTriggers` を実行 |
| 一時的にすべて止めたい | `deleteAllTriggers` を実行。データは残ります |
| 特定のソースだけ止めたい | `CONFIG` の `ENABLE_GMAIL` / `ENABLE_LINEWORKS` / `ENABLE_LINE_OA` を `FALSE` に |
| 送信だけ止めたい | `CONFIG` の `ENABLE_NOTIFY` を `FALSE` に |
| 過去日の報告を作り直したい | `CONFIG` の `REPORT_TARGET_OFFSET_DAYS` を一時的に変更 → `generateDailyReportWithoutSending` を実行 → 値を戻す |
