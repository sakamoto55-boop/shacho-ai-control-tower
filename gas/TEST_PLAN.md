# テスト計画書

## 前提条件

- Script Properties が全て設定済みであること（`showConfigStatus()` で確認）
- スプレッドシートが初期化済みであること（`testSheetInitialization()` で確認）
- `DRY_RUN = true` の状態でテストを開始すること

---

## テストケース一覧

### TC-01: LINE WORKS 通知テスト

**目的**: LINE WORKS の Incoming Webhook に通知が届くことを確認する

**手順**:
1. Apps Script エディタで `sendTestLineWorks()` を実行する
2. LINE WORKS の指定トークルームを確認する

**期待結果**:
- 「【テスト】LINE WORKS 通知確認」というメッセージが届く
- 実行ログに「✅ LINE WORKS 通知テスト送信完了」と表示される

**確認ポイント**:
- エラーが出ていないこと
- LINE WORKS にメッセージが届いていること

---

### TC-02: Gemini API 疎通テスト

**目的**: Gemini API が正しく動作し、JSON レスポンスを返すことを確認する

**手順**:
1. `testGemini()` を実行する

**期待結果**:
- 実行ログに以下が表示される：
  - `✅ Gemini API テスト成功`
  - `対応要否  : true`
  - `優先度    : 高`（または中）
  - `カテゴリ  : 見積依頼`
  - 要約・対応タスク・判断理由が日本語で記載される

**確認ポイント**:
- API キーエラーが出ていないこと
- JSON のパースエラーが出ていないこと
- 全フィールドに値が入っていること

---

### TC-03: スプレッドシート初期化テスト

**目的**: タスクシートとログシートが正しく作成・初期化されていることを確認する

**手順**:
1. `testSheetInitialization()` を実行する
2. スプレッドシートを直接開いて確認する

**期待結果**:
- 実行ログに以下が表示される：
  - `タスクシート「メール対応タスク」: ✅ 存在`
  - `ログシート「処理ログ」: ✅ 存在`
- スプレッドシートに2つのシートが存在する
- ヘッダー行（1行目）が正しく設定されている
- 「優先度」「ステータス」「カテゴリ」列にプルダウンが設定されている

---

### TC-04: DRY_RUN モードで新着メール処理

**目的**: DRY_RUN=true の状態で `manualRun()` を実行し、処理フロー全体が動くことを確認する

**前提**: `DRY_RUN = true` が設定済みであること

**手順**:
1. `manualRun()` を実行する
2. 実行ログを確認する
3. スプレッドシートの「メール対応タスク」シートを確認する
4. スプレッドシートの「処理ログ」シートを確認する

**期待結果**:
- 実行ログに `🔵 DRY_RUN モード:` の文字が表示される
- 対応必要と判定されたメールがタスクシートに登録される
- 下書きID列に「DRY_RUN_DRAFT」と記録される
- LINE WORKS 通知が「DRY_RUN スキップ」とログに出る
- Gmail に下書きは作成されない

### TC-05: 対応不要メールがタスク化されないこと

**目的**: メルマガや広告メールが AI に「対応不要」と判定されてタスク登録されないことを確認する

**テスト方法**（GeminiClient.gs の `testGeminiWithDummyEmail` を改変して確認）:

ダミーメール（広告営業のメール）で AI 判定を実行し、以下を確認する。

```
件名: 【PR】業務効率化ツールのご提案
本文: 弊社の〇〇ツールをご紹介させていただきたく…（一般的な営業メール）
```

**期待結果**:
- `requires_response: false` が返る
- `category: 営業広告` が返る
- ログシートに `SKIPPED` として記録される
- タスクシートには追加されない

### TC-06: 見積依頼メールがタスク化されること

### TC-08: 同じメールを二重処理しないこと

**目的**: 一度処理したメールが再度 `manualRun()` を実行しても重複登録されないことを確認する

**手順**:
1. `manualRun()` を実行してタスクを登録する
2. 再度 `manualRun()` を実行する
3. タスクシートの行数を確認する

**期待結果**:
- 2回目の実行では新規タスクが追加されない
- ログシートに `SKIPPED` または「既処理」相当の記録が残る
- タスクシートの行数が増えない

**仕組み**:
- ログシートの「メッセージID」列で処理済みIDを管理している
- `getProcessedMessageIds()` が処理済みセットを返し、`searchNewEmails()` でフィルタリングする

### TC-09: 返信下書きが作成されること（DRY_RUN=false）

**目的**: `DRY_RUN=false` の状態で、対応必要メールの返信下書きが Gmail に作成されることを確認する

> ⚠️ この TC は本番環境でテストすること。実行前にテスト用メールが info@lcc55.com に届いていることを確認すること。

**手順**:
1. Script Properties の `DRY_RUN` を `false` に変更する
2. `manualRun()` を実行する
3. Gmail の「下書き」フォルダを確認する

**期待結果**:
- 対応必要と判定されたメールの返信下書きが Gmail に作成される
- 下書きの宛先は元メールの送信者
- 下書き本文は日本語の丁寧な返信文（金額・契約を確定しない内容）
- タスクシートの「下書きID」列に実際の ID が記録される

**テスト後**:
- 必要なければ下書きを削除する
- `DRY_RUN` を `true` に戻す（まだ本番稼働しない場合）

### TC-11: 土日をまたいだ場合のメール処理

**目的**: 土日をまたいで月曜に実行した場合、前回成功時刻以降のメールが全て対象になることを確認する

**検証方法**（ログで確認）:

1. 金曜日に実行後、`LAST_SUCCESS_MS` が更新されることを確認
2. 月曜日の実行時に `lastSuccessMs` が金曜の値になっていることを確認
3. 土日に受信したメールが処理対象に含まれることを確認

**期待結果**:
- `LAST_SUCCESS_MS` が前回成功時の Unix 時間に設定されている
- 検索範囲が `newer_than:7d` のため最大7日前まで遡れる
- `cutoffMs` が `lastSuccessMs` の値になっていること（初回でない場合）
- 土日のメールが月曜の処理でタスク登録される

---

### TC-12: API エラー時にログへ記録されること

**目的**: Gemini API が失敗した場合にエラーがログに記録され、他のメールの処理は継続することを確認する

**テスト方法**（一時的に API キーを無効にして確認）:

1. `GEMINI_API_KEY` を一時的に間違った値に変更する
2. `manualRun()` を実行する

**期待結果**:
- 実行ログに `Gemini API エラー:` または `AI_ERROR` が表示される
- ログシートに `AI_ERROR` として記録される
- 他のメール（複数ある場合）の処理は継続される（1件のエラーで全体が止まらない）
- LINE WORKS 通知でエラー件数が分かる

**テスト後**:
- `GEMINI_API_KEY` を正しい値に戻す

## テスト実行順序（推奨）

```
1. showConfigStatus()      → 設定確認
2. testSheetInitialization() → シート確認
3. testGemini()            → TC-02 Gemini 疎通
4. sendTestLineWorks()     → TC-01 LINE WORKS 疎通
5. manualRun() (DRY_RUN=true) → TC-04 全体フロー
6. manualRun() 再実行      → TC-08 二重処理防止
7. DRY_RUN=false に変更
8. manualRun()             → TC-09 下書き作成
9. manualRun()             → TC-10 LINE WORKS 本番通知
10. DRY_RUN=false のまま scheduledMain() を待つ → 自動実行の確認
```

## よくあるエラーと対処

| エラー | 原因 | 対処 |
|---|---|---|
| `GEMINI_API_KEY が未設定です` | Script Properties 未設定 | プロパティを追加する |
| `Gemini API エラー: HTTP 403` | API キーが無効・未認証 | AI Studio で新しいキーを発行 |
| `Gemini API エラー: HTTP 429` | レート制限超過 | しばらく待ってから再実行 |
| `LINE WORKS Webhook エラー: HTTP 404` | Webhook URL が間違い | LINE WORKS で URL を再確認 |
| `スプレッドシートが見つかりません` | SPREADSHEET_ID が間違い | URL から正しい ID を取得 |
| `下書き作成エラー` | Gmail の権限不足 | アクセス許可を再確認・再承認 |
