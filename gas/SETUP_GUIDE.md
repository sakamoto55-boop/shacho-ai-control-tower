# グループ経営情報 自動収集＋日次AI報告システム 導入手順書（第1期）

対象読者：DX担当者1名（エンジニアでなくても、上から順にそのとおり作業すれば動きます）
所要時間：**合計およそ5時間**（＋設定反映の待ち時間）

---

## 0. 最初に読んでください ― 今回できないこと

このシステムは「読む・まとめる・社内に知らせる」だけを行います。
以下は**第1期では実装していません**。期待違いを防ぐため、経営者にも共有してください。

### 技術的にできないこと

| できないこと | 理由 |
|---|---|
| **個人LINEの内容取得** | 個人LINEには外部から読み取るAPIが存在しません。スクレイピング・RPA・通知読み取りも行いません。必要な情報は人が転記してください。 |
| **LINE公式アカウントの過去履歴の取得** | Messaging APIに「過去のメッセージを一覧する」機能がありません。**Webhookを登録した日より後**に届いたものだけが貯まります。 |
| **LINE WORKSトークのリアルタイム取得** | モニタリングAPIは期間を指定してCSVを作らせる方式です。即時反映はできません。 |
| **Bot が参加していないトークの即時取得** | 上記のとおりモニタリングAPI経由（日次バッチ）になります。 |
| **LINE公式アカウントWebhookの署名検証** | GASの `doPost` にはHTTPヘッダーが渡されない仕様のため、LINEが推奨する `x-line-signature` の検証ができません。代わりにURLへ合言葉を付けています（後述 STEP 4）。 |
| **前日分トークが翌朝に必ず揃うこと** | モニタリングAPIのCSV生成には遅れが出ることがあります。揃わない日は CONFIG の `LW_MONITORING_LAG_DAYS` を `1` にして「2日前」を取る運用へ切り替えてください。 |

### 方針として「あえてやらないこと」

- 顧客・取引先への**自動返信、自動送信は一切しません**。送信先は経営者と管理者（社内2名）だけです。
- 売上などの**数値をAIに計算させません**。スプレッドシートで確定した値をそのまま引用させるだけです。
- メールの**本文全文は保存しません**。Gmailが返す抜粋（先頭200文字程度）までです。
- **承認フロー（Human-in-the-Loop）は第2期**です。第1期はあくまで読み取りと報告のみです。

## 1. 全体像

```
毎日 03:00  GASが起動 → Gmail / LINE WORKS を収集 → スプレッドシートに蓄積
毎日 06:00  前日分＋経営データを事業別に整理 → マスキング → Gemini → LINE WORKSで経営者へ送信
随時        LINE公式アカウントの受信をWebhookで受け取り蓄積
```

作れるシート（`setupAll()` が自動で作ります）

| シート | 中身 |
|---|---|
| `DATA_MAIL` | メールの日時・法人・差出人・宛先・件名・要約対象フラグ・抜粋 |
| `DATA_TALK` | LINE WORKSトークの日時・トークルーム・発言者・本文 |
| `DATA_LINE` | LINE公式アカウント受信の日時・顧客・本文 |
| `CONFIG` | 動作パラメータ（上限件数・キーワードなど） |
| `CONFIG_ORG` | 法人リスト・事業区分・メールドメイン |
| `CONFIG_MAIL_TARGET` | Gmail収集の対象アドレス |
| `CONFIG_MASK` | AIに渡す前のマスキングルール（禁止ワード・電話番号などのパターン） |
| `REPORT_LOG` | 生成した日次報告の保存 |
| `RUN_LOG` | 実行記録・件数・エラー |

## STEP A. Google Cloud：サービスアカウントとドメイン全体の委任

> 全社員のメールを読む強い権限を扱います。作業は Google Workspace の**特権管理者**アカウントで行ってください。

### A-1. Google Cloud プロジェクトを作る（15分）

1. https://console.cloud.google.com/ を開く
2. 画面上部のプロジェクト選択 →「新しいプロジェクト」
3. プロジェクト名：`keiei-ai-kanseito` などわかる名前 →「作成」
4. 左メニュー「APIとサービス」→「ライブラリ」
5. 検索窓に `Gmail API` と入力 → Gmail API を開く →「有効にする」

### A-2. サービスアカウントを作る（10分）

1. 左メニュー「APIとサービス」→「認証情報」
2. 上部「＋認証情報を作成」→「サービスアカウント」
3. サービスアカウント名：`keiei-ai-collector` →「作成して続行」
4. ロールは**付けずに**「続行」→「完了」
   （Gmailの権限はロールではなく次のドメイン全体の委任で与えます）
5. 作成されたサービスアカウントをクリック →「キー」タブ
6. 「鍵を追加」→「新しい鍵を作成」→ **JSON** →「作成」
7. JSONファイルがPCにダウンロードされます。**このファイルはパスワード同等**です。
   共有ドライブに置かず、設定が終わったら削除してください。
8. 同じ画面の「詳細」タブで **一意のID（クライアントID）** の数字を控えます（次で使います）
9. サービスアカウントのメールアドレス（`....iam.gserviceaccount.com`）も控えます

### A-3. ドメイン全体の委任を許可する（15分＋反映待ち）

1. https://admin.google.com/ （Google管理コンソール）を特権管理者で開く
2. 左メニュー「セキュリティ」→「アクセスとデータ管理」→「APIの制御」
3. 下部の「ドメイン全体の委任を管理」→「新しく追加」
4. **クライアントID**：A-2 の手順8で控えた数字
5. **OAuthスコープ**：以下を1行で貼り付け

   ```
   https://www.googleapis.com/auth/gmail.readonly
   ```

   > 読み取り専用スコープだけです。送信・削除の権限は与えません。
6. 「承認」
7. 反映には通常数分、最大24時間かかります。あとの確認テストで失敗する場合は時間をおいて再実行してください。

### A-4.（推奨）監査ログを有効にする（10分）

管理コンソール →「レポート」→「監査と調査」で、サービスアカウントによるアクセスが記録されることを確認しておいてください。誰の・いつのメールを読んだかを後から追えるようにするためです。

## STEP C. LINE WORKS の設定（65分）

### C-1. プランの確認（10分）

モニタリングAPI（`monitoring.read`）は上位プランと管理者権限が必要です。
LINE WORKS の管理者画面で、モニタリング機能が使える契約かを先に確認してください。

**使えない場合**：CONFIG シートの `ENABLE_LINEWORKS` を `FALSE` にすれば、
メールとLINE公式アカウントだけで運用を開始できます（トークは報告に含まれません）。

### C-2. アプリとService Accountを作る（20分）

1. https://developers.worksmobile.com/ を管理者で開く
2. 「アプリ」→「アプリの新規追加」
3. アプリ名：`経営AI管制塔` を入力して作成
4. 作成後の画面で以下を控えます
   - **Client ID**
   - **Client Secret**
5. 同じ画面の「Service Account」→「発行」
   - **Service Account ID**（`....serviceaccount@....` 形式）を控えます
6. 「Private Key」→「発行」→ ダウンロードされた `.key` ファイルをテキストエディタで開き、
   `-----BEGIN PRIVATE KEY-----` から `-----END PRIVATE KEY-----` まで全文を控えます

### C-3. スコープを許可する（15分）

1. 同じアプリの「OAuth Scopes」→「追加」
2. 以下を追加

   | スコープ | 用途 |
   |---|---|
   | `monitoring.read` | トークのモニタリングCSV取得 |
   | `bot` | 経営者・管理者への報告送信 |

3. 保存。プランや設定によっては管理者承認が必要です。

### C-4. Bot を作って経営者に届くようにする（20分）

1. Developer Console の「Bot」→「登録」
2. Bot名：`経営AI管制塔`
3. **メンバーによるBotの利用**：管理者のみ、などお好みで
4. 登録後の **Bot ID** を控えます
5. LINE WORKS の管理者画面 →「サービス」→「Bot」で、作成したBotを**公開／利用可能**にします
6. 経営者と管理者（DX担当）のLINE WORKSアカウントで、このBotとのトークを一度開いておきます

### C-5. ドメインIDとユーザーIDを控える（10分）

- **ドメインID**：LINE WORKS 管理者画面の「基本設定」や、Developer Console の API テスト画面で確認できます
- **経営者のユーザーID／管理者のユーザーID**：管理者画面の各メンバーの詳細で確認できます
  （メールアドレス形式ではなく、`xxxxxxxx-xxxx-...` 形式のIDです）

| `LW_SERVICE_ACCOUNT` | Service Account ID | ★ |

| `LW_DOMAIN_ID` | LINE WORKS のドメインID | ★ |
| `LW_BOT_ID` | 作成したBotのID | ★ |
| `LW_PRESIDENT_USER_ID` | 経営者のLINE WORKSユーザーID | ★ |
| `LW_ADMIN_USER_ID` | 管理者（DX担当）のユーザーID。エラー通知先 | |

## STEP G. セットアップ実行とCONFIG記入（30分）

### G-1. `setupAll()` を実行する

1. Apps Scriptエディタの上部で関数 `setupAll` を選び「実行」
2. 初回は権限の承認画面が出ます →「詳細」→「（安全でないページ）に移動」→「許可」
   （自分で作ったスクリプトのため、この警告は正常です）
3. シートが9枚作られ、CONFIGに初期値が入ります

### G-2. `CONFIG_ORG` を実際の法人に書き換える

| 列 | 記入内容 |
|---|---|
| 法人ID | `ORG_KAITAI` などのまま使ってOK（半角英数） |
| 法人名 | 実際の法人名 |
| 事業区分 | `解体` / `地域支援` / `不動産` / `福祉`（報告の見出しになります） |
| メールドメイン | その法人のメールドメイン（`example.co.jp` の形。`@` は不要） |
| LINE WORKS組織名 | トークルーム名に含まれる部署名など。法人の推定に使います |
| 有効 | `TRUE` |

### G-3. `CONFIG_MAIL_TARGET` に収集対象アドレスを書く

**ここに書いたアドレスだけ**を読みます。役職者と共有アドレス（15〜20件程度）を想定しています。

| 列 | 記入内容 |
|---|---|
| メールアドレス | 対象のGmailアドレス |
| 氏名/用途 | `解体：代表` `全社：受付` など |
| 法人ID | `CONFIG_ORG` の法人ID |
| 事業区分 | `解体` など |
| 有効 | `TRUE`（一時停止したいときは `FALSE`） |

サンプル行が2件入っているので、実アドレスに書き換えて `有効` を `TRUE` にしてください。

### G-4. `CONFIG_MASK` に伏せ字ルールを追加する

電話番号・メールアドレス・口座番号・郵便番号・生年月日は最初から入っています。
これに加えて、**AIに渡したくない固有名詞**を `word` 種別で1行ずつ追加してください。

| 種別 | パターン | 置換後 | 説明 | 有効 |
|---|---|---|---|---|
| `word` | （福祉利用者の氏名） | `【利用者】` | 要配慮情報 | `TRUE` |
| `word` | （病名など） | `【伏字】` | 要配慮情報 | `TRUE` |

> 初期状態の最終行はサンプル（`有効=FALSE`）です。実際の語に書き換えて `TRUE` にしてください。

### G-5. `CONFIG` の主な調整項目

| キー | 意味 | 目安 |
|---|---|---|
| `SUMMARY_KEYWORDS` | この語を含むメール・トークだけをAIに渡す | 運用しながら追加していく |
| `MAX_MAIL_PER_TARGET` | 1アドレスあたりの1日の上限 | 100 |
| `MAX_GEMINI_CALLS_PER_DAY` | Gemini呼び出しの1日上限 | 5（コストの安全弁） |
| `MAX_AI_INPUT_CHARS` | AIに渡す文字数上限 | 60000 |
| `ENABLE_NOTIFY` | `FALSE` にすると生成のみで送信しない | 試験運用中は `FALSE` 推奨 |
| `LW_MONITORING_LAG_DAYS` | トークが前日分で揃わないときに `1` にする | 0 |
| `BIZ_SALES_RANGE` 他 | 経営データの範囲（例 `売上!A1:F30`） | 実際のシート名に合わせる |

### G-6. 経営データシートの共有

`BIZ_SPREADSHEET_ID` で指定したスプレッドシートを、
**このスクリプトを実行するアカウント**（＝あなたのアカウント）が閲覧できる状態にしてください。

## STEP H. デプロイ・Webhook登録・トリガー（25分）

### H-1. ウェブアプリとしてデプロイする

1. Apps Scriptエディタ右上「デプロイ」→「新しいデプロイ」
2. 歯車（種類の選択）→「ウェブアプリ」
3. 設定
   - 説明：`LINE公式アカウント Webhook`
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
     （LINEのサーバーから匿名で呼ばれるため必要です。合言葉で保護します）
4. 「デプロイ」→ 表示された **ウェブアプリURL** をコピー

### H-2. LINE公式アカウントにWebhook URLを登録する

1. コピーしたURLの末尾に、STEP F で決めた合言葉を付けます

   ```
   https://script.google.com/macros/s/AKfy..../exec?token=k7Qv2mZx9pLr4Ts6Wn1B
   ```

2. LINE Developers Console →「Messaging API設定」→「Webhook URL」に貼り付け →「更新」
3. 「検証」を押して成功すればOK
4. **Webhookの利用：オン**

> 以後、このURLは社外に共有しないでください。合言葉が漏れると誰でも投稿できてしまいます。
> 万一漏れた場合は `LINE_WEBHOOK_TOKEN` を変更し、Webhook URLを付け替えてください。

### H-3. トリガーを登録する

エディタで関数 `setupTriggers` を選んで実行します。以下が登録されます。

| 時刻 | 関数 | 内容 |
|---|---|---|
| 03:00 | `startDailyCollection` | 収集開始（時間内に終わらなければ自動で分割継続） |
| 03:30 | `flushLineQueue` | LINE受信の退避分を書き出し |
| 06:00 | `runDailyReport` | AI報告の生成と送信 |

> GASの時間指定トリガーは前後15分程度ずれます。06:00指定でも5:45〜6:15の到着になります。

### H-4. コードを更新したときの再デプロイ

`.gs` を書き換えたら「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →
バージョン「新バージョン」→「デプロイ」。**URLは変わりません**（Webhookの再登録は不要）。

## 3. 運用のポイント

### 毎日

- 6時前後に経営者へ報告が届くか
- 届かない日は `RUN_LOG` シートの最下部を見る（`ERROR` 行に原因が書かれています）

### 毎週

## 4. 困ったときは

| 症状 | 原因と対処 |
|---|---|
| `スクリプトプロパティ ○○ が未設定です` | STEP F の該当項目を登録する |
| `Googleのアクセストークン取得に失敗しました（HTTP 401/403）` | ドメイン全体の委任が未反映、またはスコープ違い。STEP A-3 を確認し、数時間おいて再実行 |
| Gmailは取れるが0件 | `CONFIG_MAIL_TARGET` の `有効` が `TRUE` か、対象日にメールがあるかを確認 |
| `LINE WORKSのアクセストークン取得に失敗しました` | Developer Console でスコープ `monitoring.read` / `bot` が許可されているか確認 |
| `モニタリングCSVのダウンロードURLを取得できませんでした` | 前日分がまだ生成されていない。`CONFIG` の `LW_MONITORING_LAG_DAYS` を `1` にする |
| `モニタリングCSVの列を特定できませんでした` | エラーメッセージに実際の見出しが出ます。その名前を `CONFIG` の `LW_CSV_COL_*` に追記する |
| LINE公式の受信がシートに入らない | Webhook URLに `?token=` が付いているか、`LINE_WEBHOOK_TOKEN` と一致しているか |
| `本日のGemini呼び出し上限に達しました` | `CONFIG` の `MAX_GEMINI_CALLS_PER_DAY` を増やす（コストに注意） |
| 収集が途中で止まったまま動かない | 関数 `resetCollectionState` を実行してから `startDailyCollection` を再実行 |
| 報告が長すぎて読みにくい | `CONFIG` の `SUMMARY_KEYWORDS` を絞る／`GEMINI_MAX_OUTPUT_TOKENS` を下げる |

## 5. セキュリティ上の注意

1. **サービスアカウントのJSONキーは全社員のメールを読める鍵です。**
   設定後はダウンロードしたファイルを削除し、共有ドライブやチャットに置かないでください。
2. **スクリプトプロパティの値をスクリーンショットで共有しない。**
   点検には `checkProperties()` を使ってください（設定の有無だけを表示します）。
3. **ウェブアプリURLは社外に出さない。** 合言葉つきでも公開しないでください。
4. **このスプレッドシート自体の共有範囲を絞る。**
   全社メールの件名と抜粋が入ります。閲覧者は経営者とDX担当に限定してください。
5. 退職・異動があったら `CONFIG_MAIL_TARGET` の該当行を `FALSE` にしてください。
