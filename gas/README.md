# グループ経営情報 自動収集＋日次AI報告システム（第1期 / Google Sheets + GAS）

4法人（建設・解体／地域支援／不動産／福祉・従業員約60名）に散らばった情報を
毎日自動で1つのスプレッドシートに集約し、経営統括AIが事業別に要約して
毎朝 LINE WORKS で経営者に報告する仕組みです。

**このフォルダは `src/` のNode.js製API（社長AI管制塔 Phase 1）とは独立しています。**
npmのビルド・テスト対象外です。

---

## 何をするか

```
毎日 03:00  Gmail（サービスアカウント＋ドメイン全体の委任 / 読み取り専用）
            LINE WORKS（モニタリングAPI / 日次CSV）
            を収集してスプレッドシートへ蓄積
随時        LINE公式アカウントの受信を doPost で受け取り蓄積
毎日 06:00  前日分＋経営データを事業別に整理
            → マスキング → Gemini API → LINE WORKS Bot で経営者へ送信
```

生成する報告の中身

- 3行の全社サマリー
- 事業別（解体／地域支援／不動産／福祉）の動きと気になる点
- 対応が必要そうな事項トップ3（根拠となるメール・トークの日時つき）

---

## 設計上の約束（コードで守っていること）

1. **読み取りと社内通知のみ。** 外部への送信・返信・データ変更の経路は実装していない。
   送信先は経営者と管理者の社内2箇所だけ（`09_Notify.gs`）。
2. **数値はAIに計算させない。** スプレッドシートで確定した表示値だけを渡す（`06_BusinessData.gs`）。
   件数もGAS側で数えてプロンプトに書き込む。
3. **AIに渡す前に必ずマスキング。** CONFIG_MASKの正規表現・禁止ワードで伏せ字化（`07_Masking.gs`）。
4. **認証情報はすべてスクリプトプロパティ。** コード直書きなし（`00_Config.gs` / `02_Auth.gs`）。
5. **LockServiceで多重実行防止。** 失敗はRUN_LOGに記録し、管理者へ通知（`10_Runner.gs`）。
6. **取得件数の上限をCONFIGで設定。** コストと実行時間の暴走を防ぐ。
7. **6分制限対策。** 収集を法人別・ソース別のジョブに分割し、進捗を保存して継続実行する。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `appsscript.json` | マニフェスト（必要最小限のスコープ） |
| `00_Config.gs` | シート定義・スクリプトプロパティ・CONFIG読み出し |
| `01_Setup.gs` | `setupAll()` によるシート生成・初期値投入・トリガー登録 |
| `02_Auth.gs` | Google / LINE WORKS のJWT認証（外部ライブラリ不使用） |
| `03_CollectGmail.gs` | Gmail収集（メタデータのみ・並列取得） |
| `04_CollectLineWorks.gs` | モニタリングAPIのCSV取得とパース |
| `05_WebhookLine.gs` | LINE公式アカウントのWebhook受信（`doPost`） |
| `06_BusinessData.gs` | 既存経営データシートの参照（確定値のみ） |
| `07_Masking.gs` | AI送信前のマスキング |
| `08_AiReport.gs` | プロンプト組み立てとGemini呼び出し |
| `09_Notify.gs` | LINE WORKS Botでの社内通知 |
| `10_Runner.gs` | トリガーの入口・分割実行・ロック・エラー処理 |
| `11_Log.gs` | RUN_LOG / REPORT_LOG・日時ユーティリティ |
| `12_Test.gs` | テスト関数とサンプルデータ |
| `SETUP_GUIDE.md` | 導入手順書（DX担当者向け・冒頭に「今回できないこと」） |
| `CHECKLIST.md` | 動作確認チェックリスト |

---

## 使い方（概要）

1. `SETUP_GUIDE.md` の STEP A〜H を上から順に実施する
2. `setupAll()` を1回実行してシートとトリガーを作る
3. `CHECKLIST.md` のフェーズ0から順に動作確認する

主な関数

| 関数 | 用途 |
|---|---|
| `setupAll()` | 初回セットアップ |
| `checkProperties()` | スクリプトプロパティの過不足点検 |
| `startDailyCollection()` | 収集を今すぐ開始 |
| `runDailyReport()` | 報告の生成と送信 |
| `generateDailyReportWithoutSending()` | 報告の生成のみ（送信しない） |
| `testAll()` | 送信を伴わないテストの一括実行 |
| `resetCollectionState()` | 収集が詰まったときの復旧 |

スプレッドシートを開くと「経営AI管制塔」メニューからも操作できます。

---

## 今回できないこと（重要）

- 個人LINEの内容取得（APIが存在しない。人が転記する運用）
- LINE公式アカウントの過去履歴（Webhook登録より前のメッセージは取得不可）
- LINE WORKSトークのリアルタイム取得（モニタリングAPIは日次バッチ）
- LINE公式Webhookの署名検証（GASの `doPost` にHTTPヘッダーが渡らないため。URLの合言葉で代替）
- AIによる外部への自動返信（第2期で承認フローとともに検討）

詳細は `SETUP_GUIDE.md` の冒頭を参照してください。
